# JIDU6101: install OpenWrt

The JIDU6101 is an Arcadyan-built MediaTek `6j01` router. This page is the
flashing guide for that model: the files to use, the commands that apply, and
what is different from its siblings. The reasoning behind every step is in
[Installing OpenWrt by hand](../../OPENWRT.md#mediatek-6j01-jidu-6201--6401--6601--6701).

> [!WARNING]
> Flashing replaces the stock firmware permanently. Back up first, and read the
> family guide once before you type anything.

## At a glance

| | |
| --- | --- |
| Model | JIDU6101 |
| Family | MediaTek `6j01` |
| OpenWrt target | `mediatek/filogic` |
| Route | SSH only |
| Stage 1 | `openwrt-mediatek-filogic-jiorouter_ax6000-jidu6j01-initramfs-factory.ubi` |
| Stage 2 | `openwrt-mediatek-filogic-jiorouter_ax6000-jidu6j01-squashfs-sysupgrade.bin` |
| UART pins | No published photo |
| Address after flash | `192.168.1.1` |
| Flashing status | Unlock only. No completed flash is documented. |

## What is different on the JIDU6101

The upstream 6j01 guide names 6201, 6401, 6601 and 6701, not the 6101.
Unlocking is confirmed for this model; a completed OpenWrt flash is not. If you
go ahead, you are the first documented case: keep the backup and have a UART
adapter ready before you start.

On some 6101 units the MFG partition keeps little readable text. The raw
`mtd7_MFG.bin` in your backup is still a complete copy of the partition.

## Before you start

- [ ] `./flash.sh backup` has finished, with one `.bin` per partition.
- [ ] Root SSH works: `ssh -i ~/.ssh/idu_rsa root@192.168.31.1`.
- [ ] Both image files are in one folder on your PC.
- [ ] An Ethernet cable is connected. Do not flash over Wi-Fi.
- [ ] A UART adapter at 3.3 V within reach. The SSH route should not need it,
  but it is how you get back into a unit that will not boot.

## The commands

These are the `6j01` commands with nothing left to fill in, except where
your own router's numbers are the answer. `scp` runs from your PC, in the image
folder. The rest runs on the router.

### 1. Check the partition table

```sh
ssh -i ~/.ssh/idu_rsa root@192.168.31.1
cat /proc/mtd
```

The 6j01 procedure expects `mtd6` to be `ubi2`, the vendor's spare slot.
This layout comes from the other 6j01 models. The 6101 is not documented, so if your table does not show `ubi2` at `mtd6`, stop here.

### 2. Send the temporary system

```sh
scp -O openwrt-mediatek-filogic-jiorouter_ax6000-jidu6j01-initramfs-factory.ubi root@192.168.31.1:/tmp/
```

### 3. Write it and set the boot variables

```sh
ubidetach -m 6
ubiformat /dev/mtd6 -y -f /tmp/openwrt-mediatek-filogic-jiorouter_ax6000-jidu6j01-initramfs-factory.ubi

fw_setenv bootcmd 'ubi detach; ubi part ubi2; ubi read 46000000 kernel; fdt addr $(fdtcontroladdr); fdt rm /signature; bootm 0x46000000'
fw_setenv dual_boot.current_slot 1
fw_setenv dual_boot.slot_0_invalid 1
fw_setenv dual_boot.slot_1_invalid 1
fw_setenv ipaddr
```

This is the point of no return for the stock system on `mtd6`. Keep the single
quotes: `$(fdtcontroladdr)` has to reach u-boot literally.

### 4. Boot the temporary system

```sh
reboot
```

After about a minute:

```sh
ssh root@192.168.1.1
```

`mount` shows `/` on `tmpfs`, which is how you know it is the RAM system. If
SSH refuses, open `http://192.168.1.1` and look for the LuCI login page.

### 5. Write the permanent system

```sh
scp -O openwrt-mediatek-filogic-jiorouter_ax6000-jidu6j01-squashfs-sysupgrade.bin root@192.168.1.1:/tmp/

ssh root@192.168.1.1
sysupgrade /tmp/openwrt-mediatek-filogic-jiorouter_ax6000-jidu6j01-squashfs-sysupgrade.bin
```

It writes and reboots itself. Do not touch it until it comes back at
`192.168.1.1`. In LuCI, flash the same file from **System → Backup / Flash
Firmware** and do not tick *Keep settings*.

## After it boots

Set a root password at `http://192.168.1.1` under **System → Administration**,
or over SSH:

```sh
passwd
```

The stock address `192.168.31.1` is gone. From here the router is a normal
OpenWrt box at `192.168.1.1`.

## If it goes wrong

- **Still answering at `192.168.31.1` after the reboot:** stage 1 did not take.
  You are still on stock; re-run steps 2 and 3.
- **Nothing boots:** use the UART console. No pin photo is published; compare the board with the
  upstream `uart_pins` folder first.
- **Back to stock:** `uboot_env.txt` in your backup holds the original `bootcmd`,
  `ipaddr` and `dual_boot.*` values. Restore them with `fw_setenv`, then
  `ubidetach -m 6` and `ubiformat /dev/mtd6 -y -f /tmp/mtd6_ubi2.bin` from the
  temporary OpenWrt. Do not do that from an installed system.

The [family FAQ](../../OPENWRT.md#faq) covers the rest.
